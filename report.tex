\section{Introduction}
% ============================================================

This report documents the end-to-end machine learning workflow for
Assignment 3.  The goal is to fine-tune a pre-trained language model to
classify book reviews into one of eight genres using the GoodReads dataset,
containerise the entire pipeline with Docker, and publish the trained model to
the Hugging Face Hub.

\noindent\textbf{GitHub Repository:}
\url{https://github.com/Laksh-Mendpara/MLOps-Laksh-B23CS1037/tree/Assignment-3}

\noindent\textbf{Hugging Face Model:}
\url{https://huggingface.co/Laksh-Mendpara/MLOps-Assignment-3}

% ============================================================
\section{Model Selection}
% ============================================================

\subsection{Chosen Model: \texttt{roberta-base}}

After initial experimentation with \texttt{distilbert-base-cased}, a switch
was made to \texttt{roberta-base} to improve classification accuracy.
Table~\ref{tab:models} compares the candidate models.

\begin{table}[h]
\centering
\caption{Candidate model comparison}
\label{tab:models}
\begin{tabular}{llccc}
\toprule
\textbf{Model} & \textbf{Params} & \textbf{Size} & \textbf{Approx.\ Acc.} & \textbf{Extra deps} \\
\midrule
distilbert-base-cased       & 66 M  & 260 MB & $\sim$60\%   & none         \\
\textbf{roberta-base}       & 125 M & 480 MB & $\sim$62\%+  & none         \\
microsoft/deberta-v3-small  & 140 M & 278 MB & $\sim$74\%   & protobuf     \\
\bottomrule
\end{tabular}
\end{table}

\textbf{Rationale for \texttt{roberta-base}:}
\begin{itemize}
    \item RoBERTa was trained with a more robust regime (dynamic masking, no NSP,
          larger batches) compared to original BERT.
    \item It does not require additional system libraries (unlike DeBERTa-v3 which
          needs \texttt{protobuf} for its SentencePiece tokenizer).
    \item It is available out-of-the-box with \texttt{AutoTokenizer} and
          \texttt{AutoModelForSequenceClassification}.
    \item \texttt{microsoft/deberta-v3-small} is documented as the recommended
          upgrade path once \texttt{protobuf} is added to the Docker image.
\end{itemize}

\section{Training Summary}
% ============================================================

Training was conducted with the Hugging Face \texttt{Trainer} API inside a
Docker container with GPU acceleration (\texttt{--gpus all}).

\begin{table}[h]

\section{Docker Deployment}
% ============================================================

Two Docker images implement the pipeline:

\begin{description}
    \item[\texttt{genre-train} (\texttt{Dockerfile})]
        Development image for interactive training.
        The project directory is bind-mounted (\texttt{-v \$(pwd):/app}) so
        all outputs (model, logs, results) persist on the host file system.

    \item[\texttt{genre-eval} (\texttt{Dockerfile.eval})]
        Minimal production image.  The model is \emph{not} baked in; it is
        fetched from the Hugging Face Hub at runtime via the \texttt{HF\_REPO}
        environment variable.  Evaluation runs automatically on container start.
\end{description}

\noindent Key design decisions:
\begin{itemize}
    \item \texttt{VOLUME} instructions were deliberately omitted — Docker's
          anonymous volumes for declared paths override bind-mount subdirectories,
          making output files invisible on the host.  Explicit \texttt{-v} flags
          at \texttt{docker run} time are used instead.
    \item \texttt{python:3.11-slim} base image keeps the image lean while
          supporting all required pip packages.
    \item \texttt{--network=host} enables direct Hugging Face Hub downloads
          without NAT latency.
\end{itemize}

\section{Challenges \& Solutions}
% ============================================================

\begin{table}[h]
\centering
\begin{tabular}{p{5.5cm}p{9cm}}
\toprule
\textbf{Challenge} & \textbf{Solution} \\
\midrule
\texttt{VOLUME} in Dockerfile making log/result files invisible on host &
    Removed \texttt{VOLUME} declarations; use bind-mount (\texttt{-v \$(pwd):/app}) instead. \\
\addlinespace
\texttt{trainer.push\_to\_hub(repo\_id)} silently treating the argument as a
commit message $\rightarrow$ model not uploaded &
    Changed to \texttt{model.push\_to\_hub(repo\_id)} and
    \texttt{tokenizer.push\_to\_hub(repo\_id)} which correctly accept the repo id. \\
\addlinespace
\texttt{PlainTextLogCallback.on\_log()} raising \texttt{ValueError: I/O operation on closed file} &
    \texttt{f.flush()} was outside the \texttt{with open()} block.  Moved inside. \\
\addlinespace
\texttt{microsoft/deberta-v3-small} failing with \texttt{ImportError: protobuf not found} &
    Added \texttt{protobuf>=4.25.0} to \texttt{requirements.txt}; switched default
    to \texttt{roberta-base} (no extra deps) until the image is rebuilt. \\
\addlinespace
Large dataset download (8 $\times$ gzip HTTP streams, $\sim$500 MB) &
    Added pickle cache (\texttt{genre\_reviews\_dict.pickle}) — data downloaded
    only once; subsequent runs restore from disk in $<$1 s. \\
\addlinespace
Jupyter magic (\texttt{\%matplotlib inline}) present in notebook cells &
    Removed in \texttt{.py} scripts; used \texttt{matplotlib.use('Agg')} for
    headless (Docker-compatible) plot rendering. \\
\bottomrule
\end{tabular}
\caption{Challenges encountered and their resolutions}
\end{table}

\section{Conclusion}
% ============================================================

A complete end-to-end MLOps pipeline was implemented:

\begin{enumerate}
    \item The GoodReads dataset was downloaded, cached, and split into
          6\,400 training and 1\,600 test samples across 8 genres.
    \item \texttt{roberta-base} was fine-tuned for 3 epochs using the
          Hugging Face \texttt{Trainer} API, achieving \textbf{61.7\% accuracy}
          (macro F1~=~0.61) on the test set.
    \item The model was saved locally and pushed to the Hugging Face Hub.
    \item Re-evaluation from the Hub confirmed identical metrics, validating
          the serialisation pipeline.
    \item Two Docker images encapsulate the full workflow: a training image
          and a production evaluation image.
\end{enumerate}

Accuracy can be improved by: (a) training for more epochs (4--5),
(b) switching to \texttt{microsoft/deberta-v3-small} once \texttt{protobuf}
is available in the Docker image, or (c) increasing the per-genre review sample.
